# Agent Factory v1 contract

Contract version: **1.0.1**. `src/index.ts` is the authoritative TypeBox runtime schema and TypeScript source; `openapi.json` and `fixtures.json` are generated by `pnpm --filter @agent-factory/contracts generate`. All routes return HTTP 200 for success. Lists order by `(createdAt, id)` ascending, accept an opaque last-record cursor and return `nextCursor: null` when exhausted. IDs are opaque strings and timestamps are UTC. Fixtures are synthetic examples, never proof of runtime verification.

Authenticate the operator using `POST /v1/session` with `{token}` from local server configuration. The API sets the HttpOnly SameSite session cookie `af_session`; `GET /v1/session` returns the principal and `POST /v1/session/logout` clears it. Worker requests use a separate `Authorization: Bearer ...` credential. No configuration token or secret is returned. Worker calls to agent-capable public routes must additionally send `x-job-id`, `x-lease-token`, and `x-job-attempt`. The server resolves the delegated agent from the current live run_task/learn lease, never a body actor field. An undelegated worker cannot act as an agent or approve governance. Read scope is filtered by that identity.

Mutations other than login/logout, claim and renewal require `Idempotency-Key`. Reusing a key with identical content returns the original result; changing content conflicts. `expectedVersion` uses the resource's current version. Hire decisions additionally bind the exact `manifestVersion`. The manifest deliberately excludes runtime status: §6's status is server-owned on the agent record. Identity, requester, approver, coordinator, provisioner and executing worker remain separate durable fields.

A successful claim returns `{data: Job}`; no available job returns `{data: null}`. Fencing operations require both attempt and leaseToken belonging to the authenticated worker and an unexpired lease. Renew before expiry. Stale attempts cannot emit events, publish artifacts, reserve or settle budget, complete, or fail. Complete/fail repeat idempotently with the original key. Job payloadVersion is 1 and each kind has a concrete payload: compile_manifest `{hiringRequest,agent,organization,teams}`; provision_agent/reconfigure_agent `{agent,manifest,manifestVersion}`; run_task `{agent,task,inputMessage}`; learn `{agent}`; retire_agent `{agent,reason}`. Complete with the matching typed outcome; observations do not independently authorize ACTIVE or COMPLETED. The server enforces approved versions, mandatory evidence and legal transitions.

An actionable human/agent message to an employee creates exactly one linked task/job carrying inputMessageId. Replies set inReplyTo. Delivery states are queued, consumed, replied, failed, or blocked. Inactive recipients remain visibly blocked until admission is possible. Agent-to-human messages fill the inbox without creating a run_task job. Resolving an ESCALATED task creates follow-up work and preserves the terminal original task.

Artifact publication uses a relative `agentId/jobId/attempt/filename` path and immutable opaque artifact IDs. API verifies containment under the configured persistent volume, scope, content hash, size and current lease owner. Paths containing traversal or symlink escape are rejected even if they pass basic schema checks. Browser clients fetch metadata at `/v1/artifacts/:id` and authorized bytes at `/v1/artifacts/:id/content`; no filesystem root is exposed. Accepted artifacts cannot be replaced by retries.

Memory has explicit category, owner, scope, evidence, version and expiry. Canonical writes become proposed revisions and require governance approval before superseding the old version. Tactical knowledge cannot silently mutate mission, policy, grants or canonical instructions. Budget reservations happen before execution and unknown actual cost is null, distinct from zero. Significant grants, new credential references, budget increases, reconfiguration and retirement use human governance.

The factory coordinator is persisted as a factory identity and included as metaAgentId in hiring/jobs/events. Human approvals do not imply successful provisioning. Unavailable real runtime or integrations remain unavailable. The worker must report actual verification evidence, and core-only checks do not establish the whole-system Definition of Done.

The API accepts at most 10 MiB per artifact and rejects symbolic links in stored artifact paths. Metadata is immutable; publication does not give workers permission to alter accepted content. Retrieval rechecks the accepted size and SHA-256, so tampered or missing files produce an explicit error instead of serving silently changed bytes.

Provisioning and reconfiguration require these mandatory verification check names: `runtime`, `model`, `tools`, `authentication`, `permissions`, `memory`, `communication`, `escalation`, `observability`, `evaluation`, `restart`, and `end_to_end`. Every check must pass with nonempty persisted evidence and no error. Any additional manifest-specific required checks must also pass. Resuming an agent reuses only a complete verification set bound to its exact approved manifest version.

## Compatible patch 1.0.1

The bootstrap is 1.0.0. Version 1.0.1 corrects OpenAPI/route metadata so claim and renewal do not require Idempotency-Key, matching the original protocol prose. Supplying that header remains accepted but is ignored for these lease operations. It also exports cleanResponse for API-only field filtering. All existing request/response shapes and worker payloads remain compatible.
