# Executable live acceptance (§25)

`pnpm verify:live` runs `tests/e2e/live-acceptance.mjs` against the actual API and separately running worker. It creates real hiring requests and tasks; it does not seed agents, approvals, results, model answers, or evidence. Run it in an interactive terminal. Each initial request, exact compiled manifest, canonical revision and retirement decision is printed with its digest and requires the operator to type the matching approval. There is no automatic-approval mode.

Start a clean deployment containing only the organization, teams, standards and actual source briefs. Configure the worker with the real provider API key, model, shared artifact volume and source directory. The API and worker must use the same committed revision as this checkout. A fake or deterministic model endpoint invalidates a live run, even if its reported token counts are nonzero. The runner verifies durable model events and settled token usage; it cannot attest the remote provider's identity from those records alone.

Set `E2E_API_ORIGIN`, `E2E_OPERATOR_TOKEN`, `E2E_MODEL_NAME`, `E2E_SOURCE_ROOT` and `E2E_BRIEF_DIR` in the environment without adding secrets to source control. `E2E_MODEL_NAME` must equal the worker's `MODEL_NAME`. The runner does not need or record the provider key. `E2E_BRIEF_DIR` contains approved source files only; `E2E_SOURCE_ROOT` is the host directory mounted as worker `SOURCE_ROOT`. After each dynamic agent ID is known, the runner copies the human-reviewed brief bytes into its scoped source subdirectory before provisioning. It records content hashes, rejects symlinks and conflicting existing bytes, and refuses changed source content during a run. Keep both source directories outside the git checkout so seeding does not dirty the revision being tested. Set `E2E_STATE_PATH` to an absolute path outside the checkout, one per run/deployment/revision. Default is `/tmp/agent-factory-live.json`; it contains manifests and artifact previews, so treat it as private project evidence. The runner refuses a dirty checkout and records the actual git SHA. Set `E2E_TIMEOUT_MS` to adjust each bounded wait (default 15 minutes).

```sh
pnpm verify:live prepare
pnpm verify:live live
pnpm verify:live support
E2E_STOP_ARGV='["docker","compose","kill","-s","SIGKILL","api","worker"]' \
E2E_RESTART_ARGV='["docker","compose","up","-d","api","worker"]' pnpm verify:live restart
```

With no stage argument, all four stages run in order. The stop and restart commands are explicit argv arrays executed directly, without a shell. Adjust compose files/project/service names to the deployment actually being tested. The operator reviews this command before execution; database and artifact volumes must be retained. Do not substitute an echo command or filesystem subprocess for restarting the deployed services.

| Stage | Actions and authoritative assertions |
| --- | --- |
| `prepare` | Two human-origin initial hiring requests; exact manifest approvals; twelve named provisioning checks with evidence; each real parent execution invokes `request_hire`; each descendant request retains the actual task/job/model-tool provenance; approve and verify each child; exactly four ACTIVE employees. |
| `live` | An existing child requests the fifth employee through the real model tool; approve and verify; the requesting manager sends a real actionable message through the granted `send_message` capability; the fifth completes the resulting task, publishes hash-verified bytes and replies to its agent requester; verify the child provisioning escalation targets the actual manager and the operator resolves it. |
| `support` | Approve a concrete manifest reconfiguration and verify the new version behaviorally; pause and observe an actual AGENT_INACTIVE task refusal, escalate and resume; schedule a real learning job grounded in prior evidence; require the actual lesson memory ID in a later task's `memory.retrieved` event; operator reviews output for meaningful reuse; submit canonical knowledge through the governed endpoint, assert PROPOSED before exact approval and ACTIVE after; real bounded consultant recruitment, work, governed retirement, revoked resources, preserved/transferred knowledge and a recipient retrieval task; separately recruit, work and retire another employee while retaining the original five-agent graph. |
| `restart` | Snapshot durable agents/memory/tasks; submit and observe an EXECUTING task; abruptly stop API/worker using the operator-reviewed command; restart durable services; require the same job to record lease recovery and a later fenced claim, finish with verified artifacts/reply, retain all identities, then execute additional recovered-context work. |

Initial manifests propose bounded model/spend budgets that the human reviews. Descendants inherit bounded budgets in the runtime and receive their own human approval. Model reservations and unknown-cost accounting can exhaust these limits; resolve budget governance explicitly if that happens. A budget refusal is not a reason to fabricate completion or bypass the ledger.

The checkpoint file records completed stages, object IDs and approval digests for interruption recovery. A stage prints `RECORDED` only after its assertions pass; no missing credentials, timeouts or fake fixture fallback can print live success. Exit 2 means blocked or failed and includes the immediate cause. Inspect API events and worker logs to remediate the actual failure, then resume with the same state path. Reuse is limited to the exact same clean revision and deployment. For final `main`, use a new clean deployment/state file and run all stages again.

The harness's final `LIVE WORKFLOW COMPLETE` reports only this workflow. Merge also requires the automated permission, stale lease, rollback, reconciliation/failure-path tests and browser tests. In particular, the inactive-agent admission refusal is not a permission-scope denial, and an operator resolving a correctly routed escalation does not prove an agent manager can read restricted provisioning communication. Those permission-scope and manager-access assertions belong in the combined API/runtime behavioral tests. The restart stage requires abrupt interruption of actual executing work; it blocks if the task has already completed before interruption. Do not replace the stop command with a graceful shutdown or a no-op. Never describe this runner, its validator unit tests, or a readiness HTTP probe as the complete §24 Definition of Done on their own.

`node --test tests/e2e/live-acceptance.test.mjs` tests rejection of forged/unrelated recruitment provenance, completed status without model evidence, non-settled or zero-token usage, and altered artifact bytes. These tests are deterministic validator tests and are not real-model evidence.
